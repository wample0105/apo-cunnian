# 飞书接收复用 dsh-im，捕捉工具契约保持传输无关

飞书消息进收件箱不自己实现飞书开放平台长连接，而是复用开源插件 dsh-im（MIT，飞书在其支持列表）：飞书消息经 dsh-im 变成 DeepSeek Harness 会话回合，由 Master Prompt 指挥 AI 调用存念的捕捉工具落库。存念的捕捉工具契约（输入=文字/附件、输出=条目）保持传输无关，未来若换自建长连接或其他 IM，只是换传输层，捕捉逻辑不动。

## Considered Options

- 自建飞书事件订阅 Long Connection（出站 WSS）：机械落库零 token、全自控，但要教用户自建飞书开放平台应用拿凭据，v1 集成风险与 wizard 成本最大。
- dsh-im 先行、预留自建：实质等同本决策，仅多一个不明确的迁移承诺。

## Consequences

- 每条飞书消息消耗一个 agent 回合的 token（个人灵感量级可接受）。
- 引入第三方插件依赖：dsh-im 停维会断通道；等级为「可替换传输层」而非核心。
- 飞书侧需要 @机器人或专用会话，群聊全量收听不可预期。
